# Сканер выгодных Telegram-подарков (Portals + Tonnel)

Бот следит за новыми лотами на Portals и Tonnel и присылает вам в Telegram сообщение,
когда подарок можно купить и перепродать в плюс **после всех комиссий**:

- **внутри одной площадки** — лот выставили заметно дешевле остальных такой же модели;
- **между площадками** — на одной площадке модель стоит дешевле, чем на другой.

По умолчанию бот **только присылает уведомления**. Автопокупка включается отдельно
(раздел «Автопокупка»), и лучше сначала пару дней посмотреть, как часто бывают выгодные разницы.

## Что понадобится

- Компьютер или сервер с **Python 3.10+**, который работает круглосуточно. С телефона
  запустить нельзя. Подойдёт недорогой VPS с Ubuntu.
- Telegram-аккаунт. Для сканера подходит любой. Для автопокупки нужен тот аккаунт,
  на котором лежат TON на площадках.
- 10–15 минут на настройку.

## Установка на VPS через терминал

Подойдёт VPS с **Ubuntu 22.04 / 24.04** или **Debian 12**: хватит 1 ядра и 1 ГБ памяти.
Бот сам отправляет запросы и ничего не принимает, поэтому открывать порты не нужно.

**Заранее подготовьте** (в Telegram и браузере, не на сервере):

1. Токен бота: @BotFather → `/newbot` → скопируйте токен.
2. `API_ID` и `API_HASH`: my.telegram.org → *API development tools* → создайте приложение.

**1. Подключитесь к серверу.** IP и пароль root присылает хостинг. На Windows 10/11 откройте
PowerShell, на macOS и Linux — Терминал:

```bash
ssh root@IP_ВАШЕГО_СЕРВЕРА
```

При первом подключении ответьте `yes`, затем введите пароль (символы при вводе не видны).

**2. Скачайте бота и запустите установку:**

```bash
apt-get update && apt-get install -y git
git clone -b fix/scanner-bot-review https://github.com/gytfel/podarki-p2p.git ~/podarki-p2p
bash ~/podarki-p2p/gift-arbitrage-bot/install.sh
```

- Вошли не как root (например, `ubuntu`)? Добавляйте `sudo` перед `apt-get`, `bash` и всеми
  командами ниже: `sudo nano …`, `sudo systemctl …`, `sudo journalctl …`, `sudo rm …`.
  Если команды `sudo` нет, сначала выполните `su -` (с минусом) и вводите команды как есть.
- `apt-get` пишет «Could not get lock»? Сервер только что создан и обновляется сам: подождите
  2–5 минут и повторите (`install.sh` умеет ждать сам).
- Когда исправления окажутся в ветке `main`, `-b fix/scanner-bot-review` можно не писать.

**3. Ответьте на вопросы скрипта.** Он попросит по очереди:

- токен бота, `API_ID` и `API_HASH`;
- отправить своему боту `/start` — так скрипт узнает ваш chat_id;
- номер телефона **вашего аккаунта** (не токен бота) и код из Telegram — вход делается один раз,
  сессия хранится на сервере;
- открыть @portals и @Tonnel_Network_bot с этого аккаунта.

Ошиблись в токене, `API_ID` или `API_HASH` — скрипт сам предложит ввести их заново. Прервать
установку можно в любой момент через Ctrl+C и потом запустить `install.sh` ещё раз.

Потом скрипт проверит связь с ботом и площадками (бот пришлёт тестовое сообщение) и запустит
сканер. Он работает круглосуточно и сам поднимается после перезагрузки сервера — окно SSH
можно закрывать.

Пороги прибыли, комиссии и автопокупка настраиваются в `/opt/gift-arbitrage-bot/.env`:

```bash
nano /opt/gift-arbitrage-bot/.env      # сохранить: Ctrl+O и Enter, выйти: Ctrl+X
systemctl restart giftbot              # применить изменения
```

| Команда на сервере | Что делает |
|---|---|
| `systemctl status giftbot` | работает ли бот |
| `journalctl -u giftbot -f` | лог в реальном времени (выход: Ctrl+C) |
| `systemctl restart giftbot` | перезапуск |
| `systemctl stop giftbot` | остановка |

**Обновление** (настройки и вход сохраняются):

```bash
cd ~/podarki-p2p && git pull && bash gift-arbitrage-bot/install.sh
```

Если `git pull` ругается на ветку (её удалили после переноса исправлений в `main`):

```bash
cd ~/podarki-p2p && git fetch origin && git checkout -B main origin/main && bash gift-arbitrage-bot/install.sh
```

**Войти заново или в другой аккаунт:** `systemctl stop giftbot`, удалите
`/opt/gift-arbitrage-bot/data/telegram.session` и снова запустите `install.sh`.

Где ниже в README написано `python -m giftbot check` или `python -m giftbot login`, на сервере
просто снова запустите `bash ~/podarki-p2p/gift-arbitrage-bot/install.sh`: он остановит бота,
выполнит вход и проверку и запустит бота обратно.

## Установка на своём компьютере

```bash
cd gift-arbitrage-bot
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # Windows: copy .env.example .env
```

## Настройка

1. **Бот для уведомлений.** Напишите @BotFather → `/newbot` → скопируйте токен в `BOT_TOKEN`.
2. **Ключи Telegram.** Зайдите на my.telegram.org → *API development tools* → создайте
   приложение → впишите `API_ID` и `API_HASH`.
3. **Ваш chat_id.** Выполните `python -m giftbot chatid` и напишите своему боту `/start`.
   Число, которое появится, впишите в `ADMIN_CHAT_ID`.
4. **Вход в аккаунт.** `python -m giftbot login` → номер телефона → код из Telegram
   (и пароль, если включена двухэтапная проверка). Это делается один раз.
5. **Откройте мини-приложения** @portals и @Tonnel_Network_bot с этого аккаунта хотя бы раз.
6. **Проверка.** `python -m giftbot check` — бот пришлёт тестовое сообщение и покажет,
   получилось ли загрузить данные с каждой площадки.
7. **Запуск.** `python -m giftbot run`

На сервере всё это делает `install.sh` (раздел «Установка на VPS» выше). Ручная настройка
автозапуска — в файле `giftbot.service`.

## Команды в Telegram

Команды не нужно печатать: под полем ввода есть меню с кнопками, а у ответов бота — свои кнопки.

| Кнопка в меню | Команда | Что делает |
|---|---|---|
| 📊 Статус | `/status` | состояние площадок, сколько новых лотов, сколько сделок за сутки. Под ответом: 🔄 Обновить, ⏸ Пауза или ▶️ Продолжить |
| ⏸ Пауза | `/pause` | пауза сканирования |
| ▶️ Продолжить | `/resume` | продолжить и включить остановленные площадки |
| ⚙️ Настройки | `/settings` | текущие пороги и комиссии |
| 🤖 Автопокупка | `/autobuy` | состояние и лимиты. Под ответом: ✅ Включить или ⏹ Выключить |
| 📦 Позиции | `/positions` | купленные и ещё не проданные подарки, у каждого кнопка 🗑 Закрыть |
| ❓ Помощь | `/help` | список команд |

Кнопки «Обновить», «Пауза», «Включить» и подобные обновляют сообщение на месте, а не присылают новое.
Включение автопокупки в режиме `live` и закрытие позиции кнопкой бот переспрашивает: нужно нажать
«Да». Если напечатать `/autobuy on` или `/forget 12` текстом, бот выполнит команду сразу.
В сообщении об остановке площадки есть кнопка ▶️ Включить сейчас. Команды есть и в меню «/» Telegram.

Бот отвечает только на ваш `ADMIN_CHAT_ID`. Сообщения и нажатия кнопок из других чатов игнорируются.

## Как проверяется лот

1. Цена в диапазоне `MIN_BUY_PRICE_TON`–`MAX_BUY_PRICE_TON`.
2. Быстрая оценка по кэшу минимальных цен (флоров) модели на обеих площадках. Если лот сам
   стал флором своей площадки, кэш не знает цену следующего конкурента — такой лот сразу
   проверяется вживую.
3. Если похоже на выгоду — **проверка вживую**: запрос самых дешёвых лотов этой модели
   прямо сейчас. Цена перепродажи = самый дешёвый конкурент минус `UNDERCUT_PCT`.
4. Прибыль = (цена перепродажи − комиссия продавца) − (цена лота + комиссия покупателя)
   − `TRANSFER_COST_TON` (только между площадками).
5. Уведомление приходит, только если прибыль не меньше и `MIN_PROFIT_TON`, и `MIN_PROFIT_PCT`,
   а конкурентов не меньше `MIN_REF_LISTINGS`. Иначе цена «рынка» ненадёжна.
6. Для сделки между площадками бот ещё раз проверяет, что лот не купили.

Сравниваются подарки одной **модели** (коллекция + модель). Фон и узор тоже влияют на цену,
и бот их показывает, но в расчёт не берёт. Учитывайте это, когда решаете, покупать ли.

## Автопокупка

Бот может сам покупать найденные лоты и сразу выставлять их на продажу.
**Это реальные деньги**, поэтому включается она в три шага и с жёсткими лимитами.

1. **Тест.** Поставьте в `.env` `AUTOBUY_MODE=dry` и перезапустите бота. Отправьте `/autobuy on`.
   Бот будет писать «🧪 купил бы…», ничего не тратя. Посмотрите день-два, что именно он выбирает.
2. **Лимиты.** Настройте `AUTOBUY_MAX_PRICE_TON`, `AUTOBUY_DAILY_LIMIT_TON`, `AUTOBUY_MAX_OPEN`
   и порог прибыли `AUTOBUY_MIN_PROFIT_*`. Начните с маленьких сумм.
3. **Боевой режим.** `AUTOBUY_MODE=live`, перезапуск, `python -m giftbot check` (покажет баланс
   и доступ к инвентарю), затем `/autobuy on`.

**Как проходит покупка:**

1. Сканер находит сделку и проверяет её вживую — как обычно.
2. Автопокупка проверяет свои условия: прибыль не ниже `AUTOBUY_MIN_PROFIT_*`, цена не выше
   `AUTOBUY_MAX_PRICE_TON`, дневной лимит, число покупок за сутки, число непроданных подарков,
   пауза между покупками, баланс с запасом `AUTOBUY_RESERVE_TON`, обе площадки без ошибок.
3. Покупка ровно по цене лота. Если продавец успел поднять цену, площадка откажет.
4. Бот ищет купленный подарок в вашем инвентаре.
5. Подарок выставляется чуть дешевле самого дешёвого конкурента. Если рынок за это время
   упал, подарок выставляется по цене без убытка (затраты + `MIN_PROFIT_TON`).
6. Каждые `POSITIONS_CHECK_SEC` бот проверяет инвентарь. Когда подарок пропадёт из него
   два раза подряд, бот сообщает о продаже.

**Что бот никогда не делает:**

- не покупает подозрительно дешёвые лоты — только уведомляет;
- не повторяет запрос на покупку. При сбое связи он ищет подарок в инвентаре, а не платит второй раз;
- не включает автопокупку сам. После перезапуска, сбоя площадки или неподтверждённой покупки
  она выключена, пока вы не отправите `/autobuy on`;
- не переносит подарки между площадками. При `AUTOBUY_CROSS=true` он купит лот и напишет, куда
  его перенести, но перенос вы делаете сами.

**Если бот пишет «неизвестно, прошла ли покупка»**, откройте площадку и проверьте баланс
и инвентарь. Бот продолжит искать подарок и сообщит, если он найдётся. Если разобрались
сами, закройте позицию командой `/forget номер`.

**Tonnel.** По умолчанию бот покупает только на Portals. Tonnel защищается от автоматических
покупок: каждый торговый запрос подписывается, подпись строит пакет `tonnelmp`. Добавить
Tonnel можно через `AUTOBUY_MARKETS=portals,tonnel`, но аккаунт могут ограничить, а при
обновлении защиты покупки перестанут проходить. Также в настройках Tonnel должен быть
выключен вывод купленных подарков сразу в Telegram — бот это проверяет.

## ⚠️ Проверьте комиссии

Значения в `.env.example` взяты из открытых источников и могут устареть: площадки меняют
ставки. Перед запуском сверьте в приложениях:

- `PORTALS_SELL_FEE_PCT` — сколько Portals удерживает с продавца;
- `TONNEL_BUY_FEE_PCT` — сколько Tonnel добавляет к цене при покупке;
- `TRANSFER_COST_TON` — сколько реально стоит вывести подарок с площадки и завести на другую.

Если указать комиссии ниже реальных, бот будет присылать сделки, которые на деле убыточны.

## Защиты

- **Проверка ответов.** Каждый ответ площадки сверяется с ожидаемым форматом: нужные поля
  на месте, цены — положительные числа, фильтр по модели действительно сработал.
- **Аварийный стоп.** Если формат ответа изменился, площадка выключается сразу. После
  `MAX_CONSECUTIVE_ERRORS` ошибок подряд выключается тоже. Вам приходит сообщение с причиной
  и подсказкой, что делать.
- **Пробные запросы.** Выключенную площадку бот проверяет раз в `PROBE_INTERVAL_SEC`.
  Когда она оживёт, бот включит её сам (`AUTO_RESUME=true`) или попросит `/resume`.
- **Подозрительные цены.** Лот дешевле `ANOMALY_RATIO_PCT` от рынка приходит с пометкой
  «проверьте вручную». Это может быть ошибка данных или подделка.
- **Обновление входа.** Данные входа обновляются каждые `AUTH_REFRESH_SEC`, а при ошибке
  401/403 — сразу.
- **Лимиты.** Между запросами к одной площадке выдерживается пауза со случайной добавкой.
  На ответ 429 бот выжидает столько, сколько просит площадка.
- **Логи.** Всё пишется в `data/logs/giftbot.log`, найденные сделки — в базу `data/giftbot.db`.

## Если что-то сломалось

| Сообщение | Что делать |
|---|---|
| «формат ответа изменился» | Площадка обновила API. Лог покажет, какое поле не совпало. Код разбора: `giftbot/markets/portals.py` и `giftbot/markets/tonnel.py`. |
| «ошибка авторизации» | `python -m giftbot login` заново. Если не помогает — вставьте данные входа вручную (ниже). Повторяющийся 403 может означать блокировку Cloudflare: попробуйте `PROXY`. |
| «слишком частые запросы» | Увеличьте `POLL_INTERVAL_SEC` и `MIN_REQUEST_INTERVAL_SEC`. |
| «площадка или сеть недоступны» | Обычно проходит само, бот включит площадку обратно. |

Адреса API вынесены в `.env` (`PORTALS_API_URL`, `TONNEL_*_URL`). Если площадка
переедет на другой домен, код менять не придётся.

**Ручной вход.** Если автоматический вход не работает:

- **Tonnel:** откройте market.tonnel.network в браузере и войдите. Затем инструменты
  разработчика → *Application* → *Local Storage* → значение `web-initData` → в `TONNEL_AUTH_DATA`.
- **Portals:** откройте web.telegram.org и мини-приложение @portals. Затем инструменты
  разработчика → *Network* → любой запрос к portal-market.com → заголовок `Authorization` →
  в `PORTALS_AUTH_DATA`.

Ручные данные входа со временем истекают, и бот не сможет обновить их сам.

## Безопасность

- Файл `data/telegram.session` даёт **полный доступ к вашему Telegram-аккаунту**. Не
  передавайте его никому и не выкладывайте `.env` и папку `data/`.
- Сканеру не нужны деньги на площадках: он только читает цены. Автопокупка тратит TON
  с баланса площадок — держите там только ту сумму, которую готовы доверить боту.
- API площадок неофициальное (эндпоинты взяты из открытых библиотек aportalsmp и tonnelmp).
  Площадки могут ограничить частые автоматические запросы, поэтому не ставьте слишком
  маленькие интервалы.

## Тесты

```bash
pip install pytest
python -m pytest tests
```

Тесты проверяют расчёт прибыли, разбор ответов обеих площадок, аварийный стоп, вход,
команды бота, обработку кодов ответа HTTP и сценарии автопокупки: успешная покупка,
отказ площадки, сбой связи во время покупки, все лимиты, падение рынка, продажа. С живыми площадками код проверяется командой
`python -m giftbot check`.
